# 公開作例

## カラー版

| ファイル | 内容 |
|---|---|
| reference.jpg | 最新の第1機能PSDに対応する入力イラストの公開用JPG |
| output/output.psd | Base候補の目視選択を適用した第1機能の開発試験PSD。1024×1536、171描画＋48フォルダ |
| output/coloring_reference.json | 上記PSDと一組の14パレット・35前景パーツの情報。実Base・tones・選択理由を含む |
| output/preview.jpg | 第1機能PSDの完成色プレビュー |
| coloring/lineart.jpg | 両手でうさぎを抱える別ポーズの作例用線画。二値化したPSD線レイヤーに対応するJPG |
| coloring/preview.jpg | 新しいBaseを継承したimagegen方式の実PSDプレビュー |
| coloring/output.psd | 第2機能のimagegen方式。1024×1536、91描画＋51フォルダ |
| coloring_normals/output.psd | 第2機能の法線マップ方式の比較例。1024×1536、91描画＋51フォルダ |
| coloring_normals/preview.jpg | 法線マップ方式の実PSDプレビュー |

両方式は `output/output.psd` と隣接JSONからBaseを継承しています。白布・髪は通常明部候補、肌・黒布は中間色候補を選び、下塗りが影色へ沈む問題を軽減しました。

第1機能の参照は手を振るポーズ、第2機能は両手を下げてうさぎを抱える別ポーズです。新線画を通常のprepare-coloringで領域分けし、一覧画像を目視して素材を新規に割り当てました。局所隙間補助後の445領域を、32前景パーツ＋背景へまとめています。参照のマスク・領域番号・座標はコピーしていません。

**今回の線画生成は、機能説明用の作例を作るためにimagegenを使ったものです。通常は利用者が線画を用意し、第2機能が線画を自動生成することはありません。** 着色、局所補助、PSD保存と事後チェックには通常の第2機能のCLIを使用しました。

imagegen方式は、新しい下塗りと参照PSDの完成色をCodex組込みimagegenへ渡して生成したガイドの明度を使います。`color_model: source_tones`、`tone_mapping: source_levels`で素材ごとの明暗と色を参照へ合わせました。ガイドの線や色をPSDへ直接貼っていません。

法線マップ方式は、新しい別ポーズの着色再構成から同一格子へ法線を新規推定し、既定の左上手前（光源1）から照明を計算しました。imagegen方式の着色結果を推定入力にした比較例であり、imagegenから独立した評価ではありません。`source_tones` と `source_ramp` で素材別に明暗幅・色を合わせています。保存PSDはこの光源で固定されたBase/Shadow/Highlightです。法線配列は公開例に含めていません。50光源の切替は法線を登録した作業jobとプレビュー画面で利用できます。

両PSDの32前景Baseが参照JSONのRGBを保持すること、新規割当マスクとの一致、入力二値線の完全保持、影/光の素材外画素0を検証しました。全色替え・素材・背景・明暗比較画像を目視し、事後レビューは制約付き完了。Python着色目標からのPSD読み戻しMAEはimagegen方式0.06347、法線方式0.06991、最大チャンネル差は両方1です。元絵の印象や影形状の再現点数ではありません。

制約: 法線方式は鼻の点状影、髪の艶、瞳の反射が元絵と異なるため、主例にはimagegen方式を採用しました。imagegen方式にも虹彩の明度差や細線近傍の照明ずれが残ります。下瞼の開いた線で白目の一部が肌につながる箇所は局所補助後も残り、大きな色替え時に追加修正が必要です。入力線の微小ジャギーと線主体の眉・黒目、参照由来のうさぎのフラットな色部も残ります。大きな色替えでは影・光の色も調整が必要です。Photoshop／CLIP STUDIO PAINTでの実アプリ確認は行っていません。

プレビューJPGは実PSDから作成し、EXIF/XMP・コメントを付けずに保存しています。

## トーン版

| ファイル | 内容 |
|---|---|
| manga/reference.jpg | 今回指定された第1機能の入力カラー画像の公開用JPG。カラー版とは別の原画 |
| manga/output.psd | QwenImage2.1再描画・Manga Line Extractionとツール既定値を使った第1機能のトーンPSD。2793×4096、23描画＋15フォルダ |
| manga/tone_reference.json | 上記PSDと一組の9素材のトーン情報。自動判定した濃度・ベタ可否・意味名・階層・既定の網設定を含む |
| manga/preview.png | 第1機能PSDの原寸トーン化プレビュー |
| manga/lineart.png | 第1機能PSDから取り出した線画単独PNG |
| manga_transfer/lineart.png | QwenImage2.1で作った肩ひもに手を添える別ポーズ線画の二値化PNG。実PSDの線レイヤーと一致 |
| manga_transfer/preview.png | 素材別濃度を引き継いだ第2機能PSDの原寸プレビュー |
| manga_transfer/output.psd | 参照の素材濃度・網設定を変えずに別線画へトーンを貼った第2機能のPSD。832×1248、18描画＋16フォルダ |
| manga_transfer/tone_reference.json | 上記PSDと一組の9素材のトーン情報。さらに別線画への引き継ぎに使用可能 |

第1機能（トーン版）はカラー画像を入力し、トーン化したPNG・PSDを出力します。第2機能（トーン版）はその素材情報を別線画へ引き継ぎますが、出力品質は検証中です。manga_transferのファイルは検証用として保持しています。今回のトーン版は利用者が指定した別のカラー原画から作り直しており、カラー版作例は変更していません。第1機能の画像比較は [ルートREADMEのトーン版作例](../README.md#作例トーン版) を参照してください。

第1機能は指定された海辺のカラー画像（2793×4096px）からQwen-Image 2.1 Turboで再描画しました。生成は既定の1Mpx・seed 1・8ステップ、結果は832×1248pxです。線はManga Line Extractionで元画像から抽出し、原画を変形せず生成側を原寸へ位置合わせしています。抽出線の隙間で人物と背景がつながったため、同じQwenで同じポーズの補助線画も作り、塗り分け境界だけに使用しました。全領域を目視し、顔・瞳・マフラー端を局所修正して286領域を9パーツへ整理しています。補助線画は完成PSDの線へ置き換えていません。

第2機能は `manga` のPSDとJSONを参照し、同じカラー原画からQwenImage2.1で作った別ポーズ線画へ素材・役割を新しく割り当てました。初期120領域を目視し、薄い線を塗り分け境界だけに利用して顔・耳・マフラーのフリンジの結合を補助。180領域を9パーツへ整理しています。出力線の二値化閾値192と線の画素は維持しました。局所の境界補助は作例用のPython処理で、トーン調整画面のブラシ機能ではありません。元ポーズの座標・領域番号・マスクは移していません。

**別ポーズの線画生成は今回の作例制作のために行いました。通常は利用者が線画を用意し、第2機能が自動生成することはありません。** 再描画と別ポーズ線画にはQwenImage2.1を使い、imagegenは使っていません。

第1機能の全体設定は `manga_tone.DEFAULT_SETTINGS`、各素材はbase:auto／shadow:auto／highlight:white／beta:trueと完全一致しています。Codexによる数値調整や、素材意味を理由にした白・黒・濃度の上書きはしていません。第2機能も参照の濃度・ベタ可否・網設定をそのまま継承しています。意味分類・境界の修正と、新線画へ影などの役割を割り当てる作業は行っています。

利用者の指定に従い、空・雲・海・波を「背景」1パーツにまとめています。背景の影とハイライトは別レイヤーで、第1機能はベタも独立しています。既定計算で紙色になった白い部分を、編集できる白ハイライトレイヤーへ分離しました。これはレイヤー構成の指定で、トーン数値・素材濃度・合成画素は変更していません。背景単独と影・ハイライトの各画像も実PSDから確認しています。

両例ともMangaScreen方式のdots、画像幅基準200列、白境界0.80、黒境界0.30、薄トーン0.18、濃トーン0.42、gradation 1.0、線閾値0.30、白抜き0.4、小領域600、ベタ最小面積40・最小比率0.005です。CLIの既定どおりdpiは未指定で、600dpiなどの解像度情報を追加していません。200はLPIではありません。同じ数値でも画像幅が違うため網間隔は第1機能13.965px、第2機能4.16pxとなり、第2機能には5px未満の警告が出ています。今回は既定値の結果を示すため変更していません。原寸PNGを100%で確認してください。

両例とも線・ベタ・ホワイト・パーツ別トーン、影／光／ベースOFF、1:1網点、素材一覧、位置合わせ、差分を全確認し、事後レビューは制約付き完了です。原寸PNGは実PSDの読み戻しと全画素一致。第2機能の線レイヤーは入力の二値化線と完全一致し、領域を分ける仮の補助線を含みません。PSD読み戻しのMAEと最大チャンネル差は両例とも0です。Pythonの描画目標に対する値で、カラー原画や別ポーズの形・陰影の再現率ではありません。

制約: 第1機能の線距離は再描画約4.75px・抽出線約3.39px、境界用Qwen線画約4.93pxで、細部の位置差が残ります。肌の陰影やコートの内部線は省略され、髪・コートの粒状の跡が線レイヤーにも混入しています。合成ではベタに埋もれますが、線単独の編集品質は未達です。マフラー端・目元・髪縁のマスクにも局所的な誤差が残ります。第2機能には細線・チェック柄の途切れ、フリンジの一部と袖の結合、細かな網の不均一さ、ベタに埋もれる内部線があります。夕日の反射や元の陰影形状は自動移植しません。これらを無断の数値調整で修正せず、既定値での制約として掲載しています。Photoshop／CLIP STUDIO PAINTでの実アプリ確認は行っていません。

公開PNGは画素と解像度情報だけで保存し、PSDのリソースとJSONの意味記述も確認しています。既存のカラー版ファイルは変更していません。PSDと同じフォルダのJSONを一組で保管すれば、制作時のworkフォルダがなくても新しい線画へ引き継げます。実際の準備例は [第2機能（トーン版）の手順](../docs/TONE_TRANSFER_WORKFLOW.md#付属作例を参照にする) を参照してください。
